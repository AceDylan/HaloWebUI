## 1. 统一助手库

### 1.1 两类条目

| 类别 | 存放 | 可写 | 有底座 |
|---|---|---|---|
| 用户助手 | 现有 `model` 表（`base_model_id` 非空的行），不新建表 | 按权限 | 有（推荐底座） |
| 内置模板 | `agents-zh.json` 移到前后端都能读的位置（后端 + Hermes 插件已经能读同一文件） | 只读 | 无 |

- 内置模板可直接使用（用调用方的模型或调度器选的底座）；需要升级时**另存为**用户助手，来源记为该模板。同一用户已有从该模板派生的助手时，升级那一个，不再另存。
- 工作空间现有的两个页面（「助手」= 工作空间模型、「助手库」= 内置模板）合并为一个「助手」页，用来源筛选区分。

### 1.2 字段

用户助手在 `meta.assistant` 下新增（精答现有 `meta.answer_desk` 迁移进来）：

```
meta.assistant = {
  source:   "manual" | "answer" | "team" | "discuss" | "builtin:<模板id>",
  domain:   "领域（短语）",
  version:  整数，设定（system / 描述 / 名称）每变一次 +1，手动编辑也算,
  revisions: [{version, at, source, runRef, change, system, description}]  // 最多 20 条
  archived: bool,
  createdFor: {runRef, question摘要, at}
}
```

- 名称、描述、角色提示词（`params.system`）、推荐底座（`base_model_id`）沿用现有字段。
- 统一引用格式：用户助手 `model:<id>`，内置模板 `builtin:<id>`；收藏、快照、工作台记录都用它。
- 收藏存用户设置（服务器），不再用 localStorage；首次加载时把旧的 localStorage 精选迁移过去。

### 1.3 管理功能

搜索、收藏、来源筛选（手动／精答／协作台／讨论／内置派生）、编辑、停用、归档、恢复、查看版本记录。

### 1.4 权限

- 读：本人拥有 + 共享给本人（`can_read`）。管理员在**助手库页面**可管理全部，但**自动调度的候选不包含他人的私有助手**。
- 写（手动）：`can_write_resource`。
- 自动升级：候选中有编辑权限（`can_write_resource`）的助手；还需要 `workspace.models` 权限（或管理员），否则只能「仅本次」。

## 2. 显示与可用性

### 2.1 先修 bug

「全部显示」改为读 `getModelFormPayload(model).meta.hidden`；文案改为「在模型菜单中显示 / 隐藏」，批量按钮改为「全部在模型菜单中显示 / 隐藏」。

### 2.2 状态矩阵（仅对助手；底座模型的隐藏维持原意）

| 状态 | 模型菜单 | 助手库 | 三个工作台自动选择 | 历史对话 |
|---|---|---|---|---|
| 可用 · 隐藏 | 不显示 | 可使用 | 可选 | 正常 |
| 可用 · 显示 | 显示 | 可使用 | 可选 | 正常 |
| 停用 / 归档 | 不显示 | 可管理、恢复 | 不选 | 可查看；追问用快照里的设定 + 底座继续（不依赖助手仍在线） |

「模型菜单」指以下入口，统一走一个 `isVisibleInModelMenu()` 判断：模型选择器、`@` 提及、换模型重答、侧栏助手场景、讨论席位与主持人的**模型**选择器。助手编辑器的底座下拉、聊天生图模型选择不在此列，维持现状。

### 2.3 默认值

- 自动新建：`hidden = true`。
- 自动升级：不改 `hidden`。
- 已隐藏的保持隐藏；本次改动不批量修改任何现有助手的显示状态。
- 精答：`_excluded()` 拆成「助手是否可调度」（看 `is_active` / `archived`，不看 hidden）与「底座是否可用」（仍看 hidden）。

## 3. 共用调度规则

### 3.1 三种动作

| 情况 | 动作 |
|---|---|
| 已有助手适合 | 选用 |
| 领域适合，但缺少可复用能力 | 升级（有编辑权限；否则用原助手 + 本次临时补充设定，不改原件） |
| 没有合适助手 | 新建并保存，默认隐藏（无权限则「仅本次」临时助手，不保存） |

- 一次性要求（本题细节、本次立场、本次职责）放执行上下文；只有能服务以后同类任务的能力写进助手设定。
- 创建前查重：名称相同或领域 + 描述高度重叠时改为选用/升级；内置模板命中时优先「直接使用模板」，不另存。

### 3.2 两段式调度

1. **候选初筛（确定性，不调模型）**：对问题做关键词匹配，覆盖用户助手的名称/领域/描述与内置模板的名称/描述/分组；收藏与近期用过的加权。取用户助手前 20 + 内置模板前 15，每个附 300 字设定摘要。
2. **调度模型决策**：一个共用的调度提示词（从精答的 `PLAN_SYSTEM` 抽出），输入 = 问题、背景、调度单位列表（1 个问题 / N 个成员职责 / N 个席位职责）、候选清单、权限与上限；输出每个单位的动作 + 理由。

调度器放在 HaloWebUI 后端一个共享模块（由 `answer_desk.py` 的 library / plan / normalize / write 部分抽出）。协作台的组长在 Hermes 里运行，HaloWebUI 把初筛后的候选清单随 `/plan` 请求发过去，组长按同一规则输出，写入仍由 HaloWebUI 执行。

### 3.3 各入口的调度单位

| 入口 | 单位 | 助手提供 | 模型由谁决定 |
|---|---|---|---|
| 精答 | 当前问题 1 个 | 设定 + 推荐底座 | 助手的推荐底座（现状） |
| 协作台 | 每个成员的职责 | 仅设定（冻结进任务正文） | 现有执行者/模型规则，推荐底座忽略 |
| 讨论工作台 | 每个席位 | 仅设定（注入席位 system） | 用户选的席位模型，推荐底座不替换 |

## 4. 讨论工作台

### 4.1 席位

每个席位：`模型`（用户选）+ `助手来源`（自动匹配 / 指定助手 / 通用角色）+ `职责`（本次讨论，≤120 字；现有 40 字的角色名保留作短标签）。

- 「自动匹配助手」默认开启（全局开关 + 每席可改）。
- 席位模型本身是工作空间助手时，该席位视为「指定助手 = 它自己」，不自动匹配。
- 用户指定的助手优先保留；通用角色席位只用角色名，不匹配。

### 4.2 开始讨论

1. 一次调度统筹所有自动席位：输入问题、已有上下文、讨论方式、各席位职责与模型名。
2. 展示每席的「助手名称 + 选择理由 + 选用/升级/新建」标记，可查看设定。
3. 发言时 system = 助手设定 + 席位提示（现有 `build_turn_messages`：讨论身份、职责、规则）；调用用户选的模型。

示例「是否将现有系统迁移到微服务」：

| 席位 | 自动匹配助手 | 本次职责 |
|---|---|---|
| 模型 A | 软件架构师 | 分析架构收益与适用条件 |
| 模型 B | 运维工程师 | 分析部署复杂度与维护成本 |
| 模型 C | 成本分析师 | 分析投入、风险和迁移节奏 |

### 4.3 讨论方式决定分工

| 方式 | 匹配规则 |
|---|---|
| 圆桌、头脑风暴 | 优先互补的专业视角，尽量不重复 |
| 辩论 | 专业模板提供能力，正方／反方提供本次立场；立场只进执行上下文，绝不写进助手；「评审」席按中立评审匹配，不分立场 |
| 评审 | 围绕方案、风险、验证等职责匹配；第二轮匿名互评时不暴露助手名 |
| 各自回答 | 所有自动匹配的席位**统一同一模板**（比较的是模型）；指定了助手的席位保持 |

### 4.4 主持人

不参与匹配。主持人模型若是工作空间助手，调用其底座、不带助手设定；保留现有中立汇总要求（结论 / 共识 / 分歧 / 各方立场 / 下一步）。

### 4.5 多轮与追问

- 一次提问（ask）内的多轮、继续、重试、恢复：沿用该 ask 的设定快照，不重新调度。
- 追问（新 ask）：自动席位按新问题重新匹配（可能沿用上次结果）；指定助手与通用角色席位保持；`/ask` 接口改为允许按席位重新调度。

## 5. 控制自动更新与新增数量

- 一次运行只做一次调度，统筹所有单位；同一助手可被多个席位/成员复用。
- 同一次运行多个单位都要升级同一助手：合并能力要求，只生成一个版本。
- **单次运行上限**：新建 ≤ 2、升级 ≤ 2；超出部分降级为「仅本次」。
- 临时立场、单题细节不进永久助手。
- 写入时机：
  - 精答、讨论：实际开始运行时写（精答现状即如此）。
  - 协作台：计划**批准启动**时写；草拟、重新规划、取消、删除草稿都不写，草稿里只存「待执行的变更」。
- 幂等：调度结果与已执行的写入记录在运行里（精答 run / 讨论 ask / 协作台 plan），带运行 id；重试、断线重连、重复点击「开始」复用同一结果，不再新建或升级。
- 并发：写入时带期望版本号，版本已变 → 重读后合并一次，仍冲突则本次改用「仅本次」。
- 匹配失败（调度超时/格式错/无候选）：保留已有手动选择，否则用通用角色，并在界面写明原因；不阻塞运行。

## 6. 独立使用入口、版本与快照

### 6.1 入口

- 助手库每个条目：「开始对话」（推荐底座 + 设定）、「用于精答」（跳过调度直接用它）、「用于协作」（预填为某成员的助手）、「用于讨论」（预填为某席位的指定助手）。
- 普通聊天新增「选择助手」：在**当前模型**上套用设定（复用现有临时助手机制 `activeAssistant`，扩展到用户助手）。
- 首页精选读统一收藏。

### 6.2 工作台展示

三个工作台都显示「选用 / 升级 / 新建 / 仅本次」，可查看设定和本次变更（diff）。自动新建的可一键「显示到模型菜单」。

### 6.3 版本与撤销

- 每次设定变更 +1 版本，记录来源（手动 / 哪个工作台 / 哪次运行）。
- 撤销：只撤销某次运行造成的那一版；当前版本 ≠ 该运行写入的版本 → 提示「之后又改过」，给出 diff，由用户手动处理。

### 6.4 快照

- 精答 run、讨论 ask、协作台任务各自保存所用设定的完整快照（名称、版本、设定全文、来源）。
- 普通对话：设定快照写进对话参数，后续追问不受升级影响；助手有新版本时提示可切换。
- 历史记录显示当时的版本号与设定，不依赖修订记录是否还保留。

## 7. 实施顺序

## 8. 验收标准

1. 「全部显示」能把隐藏的助手恢复显示；全部隐藏后，§2.2 清单里的所有入口都看不到助手，三个工作台仍能自动选到。
2. 管理员下架（隐藏）的**底座模型**不会被任何工作台的自动调度选为底座。
3. 任一工作台创建的助手，其他两个工作台和普通聊天都能复用；内置模板可直接使用，升级后成为用户助手且来源可查。
4. 讨论的每个自动席位都匹配到模板，实际发言的 system 包含该模板完整设定，调用的是用户选的模型；主持人 system 不含任何助手设定。
5. 用户选定的模型、指定的助手、辩论立场都被保留；立场文字不会出现在任何永久助手的设定里。
6. 同一 ask 内多轮/继续/重试、协作台重试、重复点击开始：不产生新的新建或升级；放弃/重新规划协作台草稿不产生任何助手写入。
7. 管理员自动调度不读取、不修改其他用户的私有助手；无 `workspace.models` 权限的用户只得到「仅本次」。
8. 单次运行新建、升级各不超过 2 个；同一助手一次运行只多一个版本。
9. 升级后已经开始的运行和普通对话的后续追问仍用原版本；历史记录能查看当时版本；撤销在有后续修改时被拦下并提示。
