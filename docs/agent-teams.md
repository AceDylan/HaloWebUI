# 协作台（Agent Teams）

HaloWebUI 里的多代理协作：一位负责人（team-lead）拆分工，几位成员按依赖并行/接力完成，整个过程在同一个网站里看得见、管得住、能回放。执行仍由 Hermes 和现有 runner 负责，没有新客户端、新登录或新服务。

## 怎么用

- **入口**：侧栏「协作台」（/teams）；或在聊天顶栏「···」菜单点「协作任务」（会关联当前对话，协作台里有「返回对话」）。
- **发起**：写下目标 → 负责人做计划（一次模型调用，不启动任何成员）。
- **审批**：看成员分工（每位成员可选执行来源：Hermes 代理 / reclaude）、按依赖分层的任务、预计同时执行人数（本机上限 2）。可以「批准并开始」「按意见重新规划」或「取消」。普通聊天不会自动启动多代理。
- **工作台**：
  - 成员条：负责人和每位成员现在在做什么（执行中 / 等待派发 / 等待前置任务 / 等你回复 / 额度等待 / 失败 / 已停止 / 已完成）。
  - 依赖任务板：一列一个依赖深度，并行任务上下排列；实线 = 前置已完成，流动虚线 = 前置执行中，灰虚线 = 还在等；等待中的任务写着在等谁。点任务看详情。
  - 通讯与日志：成员留言、完成交接（交给谁）、你的补充说明及其送达状态、工具记录、状态变化。全部来自真实记录。
  - 详情：任务说明、每次执行尝试（reclaude 成员会列出对应的 runner 运行和续跑关系）、结果、按需加载的日志；可以给该成员补充说明、重试失败的任务。
- **控制**（三件不同的事）：
  - 回放条的「暂停回放」只影响画面；
  - 「暂停派发」：不再开始新任务，正在执行的成员做完手上的；
  - 「停止执行」：结束正在执行的成员（reclaude 运行会被停止），不会被自动恢复，也不能再继续。
- **回放**：从头回看，0.5/1/2/4 倍速，可拖时间轴；成员、任务板、统计和通讯都对应同一时点。回放只读已有记录，不会触发任何模型、工具、消息或重试。长时间没动静的间隔会被压缩。
- **手机**：同一页面换成「任务 / 成员 / 通讯」标签，不显示画布。

### 补充说明什么时候送达

| 情况 | 送达方式 | 显示 |
|---|---|---|
| Hermes 成员正在执行 | 成员每 ≥6 秒检查一次，当前这批工具调用结束后读到 | 已送达（运行中注入） |
| 成员刚开工、读取任务时 | 任务评论本身就在它读到的内容里 | 已送达（成员读取任务时看到） |
| 任务还没开始 / 重试 | 随下一次执行尝试的上下文 | 已随新的执行尝试送达 |
| reclaude 成员正在执行 | 不能中途收消息：它这一轮结束后，用同一会话续跑送达 | 已通过续跑送达 |
| reclaude 提问（QUESTION） | 你的回答直接交给同一会话续跑 | 已通过续跑送达 |

在送达之前一律显示「排队中」；任务结束前都没送达会显示「未送达（任务已结束）」。

## 架构

- **任务事实源 = Hermes Kanban**。每个协作任务一个看板 `halo-<id 前 16 位>`（`~/.hermes/kanban/boards/`）：任务、依赖、执行尝试、评论、事件都在 Kanban 自己的表里。派发器（网关内置）真正检查依赖：前置没完成的任务不会被领取。
- **归属与审批 = HaloWebUI `agent_team` 表**：谁发起、哪个对话、批准前的计划、对应的看板。所有接口按用户隔离（管理员也只看自己的）。
- **Hermes 插件 `halowebui-teams`**（本仓库 `integrations/hermes-plugin/halowebui-teams/`，见其 README）：`/v1/halo-teams` 接口（计划、建看板、快照、事件、详情、补充说明、暂停/恢复/停止、重试），worker 内的钩子（成员工具调用、原生子代理、说明送达），reclaude 执行桥接。
- **执行来源**：Hermes 成员由 Kanban 派发器以 `default` profile 启动（成员身份记在看板元数据里）；reclaude 成员由插件桥接直接调用 `reclaude-run.sh`（额度等待、提问、续跑、停止都按 runner 自己的语义映射），这些 run 不发聊天通知、不被 autopilot-supervisor 接管。
- **实时**：页面可见时每 2.5 秒按游标增量拉事件，隐藏时 30 秒；断线自动退避重试、恢复后补齐；完成后停止轮询。事件带「事件后的任务状态」，回放就是按顺序折叠；历史与当前状态不一致时页面会明确说明。

## 开关与限制

- 关闭：HaloWebUI 环境变量 `ENABLE_AGENT_TEAMS=false`（接口 404、入口隐藏）；Hermes 侧从 `plugins.enabled` 去掉 `halowebui-teams` 并重启网关。
- 并发：`kanban.max_in_progress: 2`（全机，含 reclaude 成员）；reclaude 成员同时最多 1 个。
- 已知限制：
  - 普通聊天里 Hermes 自己派出的子代理（delegate_task）仍显示在聊天的工具块里，不进协作台；协作台显示的是团队成员及其子代理。
  - 一个团队的成员共用一个工作目录（`/root/work/agent-teams/<看板>`），计划要求并行任务写不同文件。
  - 计划批准前只能调整成员的执行来源，其余改动请「按意见重新规划」。
  - 停止是终态；暂停派发可以恢复。
  - reclaude 的额度等待、自动续跑、失败目前只用模拟 runner 验证过；真实额度窗口遇到时以页面上的「额度等待」为准。
