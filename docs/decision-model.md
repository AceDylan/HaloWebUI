# 辅助决策模型

设置 → 界面 → 对话功能 → 「辅助决策模型」。默认「沿用现有逻辑」。选了模型后，自动分流、精答、讨论、协作、视频工作台里仍为「自动」的选择先交给它判断；手动指定的不变，失败时回到各模块原来的逻辑。正文回答、成员执行、总结、需求改写、标题、配图仍由各自流程里的模型完成。

## 设置

- 存在服务器上的用户设置 `settings.decision_model = {model, updated_at}`（`model` 是带连接归属的选择 ID，同名模型在不同连接下互不混淆）；按用户隔离，换设备、刷新、重新登录都保留。`POST /api/v1/decision-model/ {model: null}` 清空 = 恢复默认。
- 候选：用户能用的文字基础模型（与工作台的 bases 相同）和 Jev 类判断模型（`is_system_one_entry` 的基础模型）；保存时校验在候选里。设置的模型后来被删、停用或失去权限时，设置页提示「已不可用」，各模块按原逻辑决定。
- 每次决策都从数据库读当前设置（`decision_model.current`），改了或清空后，下一次新发起的决策就用新配置。

## 协议

所有模块用同一种请求：Jev（TypeSafe System One）的 `{state, questions}`，题型 choice / score / noul，选项由各模块从自己的候选集合构造（键都是短 ID，映射回模型/助手/执行器）。

- Jev 模型：经 OpenAI 路由的 Jev 钩子，用该连接自己的 URL 和密钥直接 `POST …/systemone`，返回原始 `answers`（`metadata.systemone_request`）。在 `metadata.task` 分支和 gpt-chat 拟题之前处理，不渲染 Markdown 表格，也不改用其他模型。
- 其他文字模型：同一请求加一段协议说明，按 Jev 的答案格式回 JSON（可附一句中文理由）。
- 结果先过 `check_answers`（选项之外、缺题、越界一律不用），再映射成该模块原有规划器的 JSON，走原有校验（权限、能力、候选范围、数量上限、只分析、联网开关、协作审批）。
- 超过 8 题拆成多个请求并发；决策过程中再请求决策会被拒绝（防递归）。

## 各模块

| 模块 | 交给决策模型的 | 仍由原流程负责的 |
| --- | --- | --- |
| 自动分流 | 方式（精答/讨论/协作，只列可用的）、是否明确要求执行 | 只分析判定、协作可用性检查；手动指定方式时不调用 |
| 精答 | 助手（候选助手/模板/「都不合适」）、回答模型、是否联网 | 选「都不合适」时由调度模型设计或升级助手；用户在助手库点名的助手不变 |
| 讨论（主持人安排） | 讨论形式、轮数、每个席位的模型（按概率依次取未占用的） | 角色和职责由主持人先写；辩论无正反方时补正方/反方；各自回答 1 轮、独立评审 2 轮 |
| 讨论（匹配助手） | 每个自动席位的助手（候选/通用角色/「都不合适」） | 「都不合适」的席位由原调度设计；用户点名的席位不变 |
| 视频工作台（提示词增强·分析需求） | 是否联网查资料（「联网搜索」开着时）、是否先交给精答/讨论（「需要时先精答·讨论」开着时；选项注明耗时，没把握选不需要） | gpt-chat 照常同时写分析（交给精答/讨论的问题、搜索词；接入后无论它怎么选都写问题，没写时用需求原文），决策失败就用它的选择；联网、精答/讨论本身和改写需求不变；生图工作台不接入 |
| 协作 | 每位成员的执行器（只列当前可用的）、Hermes 模型、助手（保留负责人选择或换成库里的） | 负责人（Hermes）写计划；HaloWebUI 把选择交给 Hermes `POST /v1/halo-teams/plan/decide` 再校验；目标点名/手动指定的执行器、手动模型、「用于协作」的助手、生图成员不变；审批流程不变 |

## 回退与记录

决策模型不可用、超时（自动分流 25 秒、其余 45–60 秒）、无权限、被删除或答案不合法时，返回无结果，模块照原逻辑走一次；决策发生在创建/启动任何东西之前，不会重复派发。原逻辑也失败时沿用原有兜底。

每次都留一条记录（模型、选择、是否回退、简短原因，不含上游原文和凭据）：自动分流回执 `data.decision`（`routing_model` 在采用时为决策模型）、精答 `run.plan.decider`、讨论 `ask.planning.decider` / `ask.matching.decider`、协作 `plan.decider`（执行器/模型来源记为 `decision`）、视频工作台增强任务 `plan.decider`（分析需求一步显示「辅助决策 xxx：先交给精答…」或「辅助决策没用上（原因）」，制作对话里等待增强时的状态行同样显示）。日志行 `[DECISION] module=… model=… fallback=0|1`。界面在对应位置显示「辅助决策 xxx」或「没用上（原因）」。

## 回滚

`git revert` 本功能提交后由 CI 构建并部署；Hermes 插件改动需网关平滑重启。无数据库迁移；用户设置里的 `decision_model` 键旧版本会忽略。只想停用：设置页「恢复默认」。
